# Security policy

Security fixes are considered for the current source on the default branch. No maintained older release branches or response-time guarantees are currently declared.

## Reporting a vulnerability

Open the repository's [Security page](https://github.com/aphrofluff/Nulluxion/security). If GitHub offers **Report a vulnerability**, use that private reporting form. Its availability depends on repository settings; this document does not establish a private email address or other private channel.

If no private reporting option is available, open a [GitHub issue](https://github.com/aphrofluff/Nulluxion/issues/new) containing only a brief request for a private security contact. Do not post exploit instructions, sensitive files, personal data, or credentials in that public issue. Wait for the maintainer to provide a reporting route before sharing details.

In a private report, include the affected revision or release, Windows version, prerequisites, expected and observed behavior, impact, and minimal reproduction steps. Review logs and recovery records before sharing: they can contain local paths, monitor identifiers, and display configuration.

For ordinary display compatibility or recovery problems, use the normal issue tracker with sanitized diagnostics. If a monitor remains off, use its physical controls and restore your layout in Windows; see the recovery guidance in [README.md](README.md).
